How a Website Thinks

The browser reads files in an order and builds the page.

When someone visits the robot, the browser first opens index.html. The HTML tells it to load the CSS, the job data, and the JavaScript.

index.html: the loading order
<link rel="stylesheet" href="./styles.css" />

<script src="./jobs-data.js"></script>
<script src="./app.js"></script>
<link ...>
Loads the CSS before the page is shown, so the page has its design.
jobs-data.js
Loads the job information first. The brain needs this memory.
app.js
Loads the behavior second. Now JavaScript can use the job information.
The big ruleIf one file needs information from another file, load the information first. Order matters.
PracticeCreate three empty files named practice.html, practice.css, and practice.js. Link the CSS near the top of the HTML and the JavaScript near the bottom.

Code Punctuation

Symbols are instructions, not decoration.

{ }Curly bracesHold a group of instructions or an object.
( )ParenthesesPass information into a function or control a condition.
[ ]Square bracketsHold a list called an array.
" "QuotesHold text called a string.
=AssignmentPuts a value into a named container.
===Exact comparisonAsks whether two values are equal.
.DotOpens a property or tool belonging to something.
;SemicolonMarks the end of a JavaScript instruction.
=>ArrowA short way to write a function.
A small JavaScript object
const student = {
  name: "Kieron",
  skills: ["Python", "JavaScript"],
  isLearning: true
};

console.log(student.name);

student is the container. The curly braces hold related facts. student.name means, “Open student and give me its name.”

Most beginner errors are tinyA missing quote, bracket, comma, or brace can stop a file. Read error messages from the first reported error, because later errors may be caused by the first one.

HTML: The Skeleton

HTML says what each piece of content is.

A complete tiny webpage
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <title>My First App</title>
    <link rel="stylesheet" href="./styles.css" />
  </head>
  <body>
    <header>
      <h1>My First App</h1>
    </header>
    <main>
      <section>
        <h2>My Projects</h2>
        <button id="helloButton" type="button">Say Hello</button>
      </section>
    </main>
    <script src="./app.js"></script>
  </body>
</html>
<head>
Information for the browser: title, character rules, phone sizing, and CSS.
<body>
Everything the person can see or interact with.
<header>
The top identity area of the page.
<main>
The primary content. Most pages should have one main element.
<section>
A meaningful group of related content.
id="helloButton"
A unique name JavaScript can use to find this exact button.

The robot's reusable template

The job detail panel uses an HTML <template>. A template is a hidden blueprint. JavaScript copies it whenever a job is selected.

index.html: hidden blueprint
<template id="detailTemplate">
  <h2 data-field="title"></h2>
  <p data-field="company"></p>
  <a data-field="applyUrl">Open Application</a>
</template>
Why data-field?data-field is a custom label. It gives JavaScript a stable place to insert a title, company, or link.

CSS: Appearance and Layout

CSS selects HTML and gives it visual rules.

styles.css: reusable design values
:root {
  --ink: #17202a;
  --surface: #ffffff;
  --green: #126b5f;
  font-family: Arial, sans-serif;
}

body {
  margin: 0;
  background: var(--surface);
  color: var(--ink);
}

.button {
  border-radius: 6px;
  padding: 10px 14px;
  background: var(--green);
  color: white;
}
:root
The highest level. We place reusable design variables here.
--green
A custom variable. Change it once and every var(--green) changes.
body
Selects the whole visible page.
.button
A period means “select every element with class button.”
property: value;
The basic CSS sentence. Example: color: white;.

Grid creates columns

styles.css: robot workspace
.workspace {
  display: grid;
  grid-template-columns: 420px minmax(0, 1fr);
  gap: 14px;
}

This creates two columns. The first is 420 pixels wide. The second takes the remaining space. The gap places 14 pixels between them.

PracticeMake three boxes. Put them inside a parent with display: grid and grid-template-columns: repeat(3, 1fr).

Responsive Design

The same page must rearrange itself for smaller screens.

styles.css: phone breakpoint
@media (max-width: 820px) {
  .workspace {
    grid-template-columns: 1fr;
  }
}

@media (max-width: 560px) {
  .toolbar {
    grid-template-columns: 1fr;
  }
}

@media means, “Only use these rules when this condition is true.” At 820 pixels or narrower, the two-column workspace becomes one column. At 560 pixels or narrower, every filter gets its own row.

Responsive thinkingDo not build a separate phone website. Build one flexible website whose layout changes at sensible widths.
PracticeGive a heading a desktop font size of 40px. Inside a media query, change it to 28px.

Search and Filters

Filtering asks every job a yes-or-no question.

app.js: simplified filter
function filteredJobs() {
  const query = searchInput.value.trim().toLowerCase();

  return data.jobs.filter((job) => {
    const searchableText = [
      job.title,
      job.company,
      job.location
    ].join(" ").toLowerCase();

    if (query && !searchableText.includes(query)) {
      return false;
    }

    return true;
  });
}

filter visits each job. Returning true keeps the job. Returning false removes it from the displayed list. The original dataset remains unchanged.

trim()
Removes extra spaces at the beginning and end.
toLowerCase()
Makes capitalization irrelevant.
join(" ")
Combines several pieces of text into one searchable sentence.
includes(query)
Checks whether the search text appears inside the sentence.
!
Means “not.” It reverses true and false.
PracticeCreate three sample products and filter them by category. Then add a search term.

Rendering Jobs on the Page

Rendering means turning data into visible HTML.

app.js: data becomes job buttons
jobResults.innerHTML = jobs.map((job) => {
  return `
    <button class="job-result" data-job-id="${job.id}">
      <strong>${job.title}</strong>
      <span>${job.company}</span>
      <span>${job.score}</span>
    </button>
  `;
}).join("");

map transforms each job into an HTML string. join("") combines all those strings. innerHTML places the finished result inside the page.

Security ruleWhen text comes from outside your own code, escape it before placing it into innerHTML. The robot uses escapeHtml() to prevent text from becoming executable HTML.
app.js: safe text
function escapeHtml(value) {
  return String(value)
    .replace(/&/g, "&amp;")
    .replace(/</g, "&lt;")
    .replace(/>/g, "&gt;")
    .replace(/"/g, "&quot;");
}

Clicks, State, and Browser Storage

State is the information that changes while the app is being used.

app.js: selecting a job
button.addEventListener("click", () => {
  selectedId = button.dataset.jobId;
  renderResults();
  renderDetail();
});

The click updates selectedId. Then the list and detail panel render again. The new state creates a new view.

Saving information after refresh

app.js: localStorage
const storageKey = "jobApplicationRobotState.v1";

function saveState() {
  localStorage.setItem(
    storageKey,
    JSON.stringify(state)
  );
}

function loadState() {
  const savedText = localStorage.getItem(storageKey);
  return savedText ? JSON.parse(savedText) : {};
}

localStorage is a small notebook inside the browser. It only stores text. JSON.stringify turns an object into text. JSON.parse turns the text back into an object.

Privacy warningLocal storage is convenient, not a vault. Never store passwords, Social Security numbers, banking information, or secret API keys there.

The Job Collector

This Node.js script asks public job sources for current listings.

collect-jobs.mjs: request JSON
async function fetchJson(url) {
  const response = await fetch(url, {
    headers: {
      Accept: "application/json"
    }
  });

  if (!response.ok) {
    throw new Error(`Request failed: ${response.status}`);
  }

  return response.json();
}
async
This function must wait for work that takes time.
await
Pause this function until the internet response arrives.
fetch(url)
Ask a web address for information.
response.ok
Whether the request succeeded.
throw new Error
Stop this path and report a useful problem.
response.json()
Convert the response into JavaScript data.

Collect several sources together

collect-jobs.mjs: parallel collection
const sourceResults = await Promise.allSettled([
  collectGreenhouse(),
  collectJobicy(),
  collectRemotive(),
  collectTulane(),
  collectOchsner(),
  collectEntergy()
]);

Promise.allSettled starts all collectors and waits for every result. If one source fails, the other sources can still succeed. That is more reliable than letting one failure destroy the entire run.

Important boundaryOnly collect information a website publicly provides and allows you to access. Respect terms, rate limits, privacy, and robots rules. Never bypass logins or technical protections.

Matching Jobs and Writing Letters

The robot uses transparent rules, not magic.

collect-jobs.mjs: simplified scoring
function scoreJob(job) {
  let score = 40;

  if (job.description.includes("SQL")) {
    score = score + 10;
  }

  if (job.description.includes("Python")) {
    score = score + 10;
  }

  if (job.title.includes("Senior")) {
    score = score - 10;
  }

  return Math.min(99, Math.max(20, score));
}

The real scoring function checks role families, resume skills, location, years of experience, and seniority. Adding points represents evidence of fit. Subtracting points represents a gap.

Personalization uses template strings

collect-jobs.mjs: letter building
function buildCoverLetter(job, fit) {
  return [
    "Dear Hiring Team,",
    "",
    `I am applying for the ${job.title} position with ${job.company}.`,
    "",
    `My experience connects with ${fit.skillsMatched.join(", ")}.`,
    "",
    "Sincerely,",
    "Kieron Christopher Haynes"
  ].join("\n");
}

This creates a list of paragraphs, inserts job-specific values, and joins the lines with \n, which means a new line.

Authenticity ruleAutomation should organize true experiences, not invent qualifications. Every final letter still needs human review for tone, accuracy, and the exact employer.

The Server and the Tests

The server delivers files. Tests prove important facts.

server.mjs: smallest useful server idea
import { createServer } from "node:http";

createServer((request, response) => {
  response.writeHead(200, {
    "Content-Type": "text/plain"
  });
  response.end("Hello from my server");
}).listen(4174);

The real server only permits known public files. This is called an allowlist. Unknown paths receive a 404 response.

validate-data.mjs: promises as tests
assert.equal(
  jobs.length,
  500,
  "The dataset must contain exactly 500 jobs."
);

assert.equal(
  new Set(jobs.map((job) => job.applyUrl)).size,
  500,
  "Every application URL must be unique."
);

An assertion says, “I expect this to be true.” If it is false, the test stops and explains which promise was broken.

PracticeWrite an assertion that expects an array named projects to contain exactly three items.

How to Work in VS Code

Make small changes, inspect them, and keep working versions.

  1. Open VS Code.
  2. Choose File → Open Folder.
  3. Open the job-application-robot folder.
  4. Use the Explorer on the left to open a file.
  5. Change one small thing.
  6. Save with Ctrl+S.
  7. Refresh the browser and inspect the result.
  8. Read the browser console or terminal if something fails.
CommandWhat it does
node server.mjsStarts the local robot at port 4174.
node tests/validate-data.mjsRuns the data safety checks.
node scripts/collect-jobs.mjsRefreshes the live job dataset.
git statusShows files you changed.
git diffShows the exact changed lines.
git add filenameSelects a file for the next saved Git version.
git commit -m "Explain change"Creates a named version in Git history.
git pushSends committed versions to GitHub.
Do not begin by changing ten filesChange one idea at a time. Test it. Then commit it. Small steps make mistakes easier to understand and undo.

Build Your Own Small App

Use the same architecture without copying the whole robot.

Project idea: Personal Project Tracker

  1. Create index.html, styles.css, and app.js.
  2. Make a header with the app name.
  3. Create a form with project name and status.
  4. Create an empty <div id="projects">.
  5. In JavaScript, create an empty projects array.
  6. When the form is submitted, create a project object.
  7. Push the object into the array.
  8. Render every object as a visible row.
  9. Save the array with local storage.
  10. Add CSS and one phone media query.

function addProject(name) {

  saveState();
  render();

function render() {

}

function saveState() {
