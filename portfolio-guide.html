Start with zero coding experience

How this portfolio was built—one understandable piece at a time.

This course uses the real Kieron Christopher Haynes portfolio as your first web-development classroom. You will learn what every file does, how each page section is constructed, how the interactive features work, and how to safely make and publish your own changes.

HTML

The structure

Headings, paragraphs, buttons, images, sections, and the meaning of the page.

CSS

The presentation

Color, spacing, typography, layout, responsive behavior, and visual polish.

JavaScript

The behavior

Tabs, video controls, animation, clicks, keyboard actions, and changing the page.

You do not need to memorize everything.

Your first goal is to recognize the pieces and understand how they connect. Confidence comes from making small changes, refreshing the page, and observing what happened.

01

The mental model

What happens when someone opens your website?

A website is a group of files that a browser reads. When someone visits your portfolio address, GitHub Pages sends those files to Chrome, Safari, Edge, or Firefox. The browser reads the files and turns them into the page you see.

1Visitor enters your URL
→
2GitHub Pages sends files
→
3Browser reads HTML, CSS, and JS
→
4Portfolio appears

HTML is the building frame

It says, “this is a heading,” “this is a picture,” and “this is the experience section.”

CSS is the interior design

It decides the colors, sizes, positions, spacing, borders, and mobile layout.

JavaScript is the electricity

It reacts when a visitor clicks a tab, opens a film, presses Escape, or resizes the window.

Assets are the content files

Images, film thumbnails, game artwork, and your résumé PDF live in asset folders.

Plain English: HTML decides what exists, CSS decides how it looks, and JavaScript decides what it does.

Language one

HTML basics: tags, elements, and attributes

HTML stands for HyperText Markup Language. It is not a programming language that calculates things. It is a markup language that labels content so the browser understands its meaning.

<a class="primary-button" href="#experience">View Experience</a>
<a — opening tag for a link class="primary-button" — a CSS label href="#experience" — where the link goes View Experience — visible text </a> — closing tag

Common HTML elements used in your portfolio

ElementMeaningPortfolio use
<header>Top area of a pageLogo, navigation, résumé button
<nav>Navigation linksLinks to Experience, Skills, Game, and Contact
<main>Main page contentWraps all major portfolio sections

04

Language two

CSS basics: selectors, properties, and the box model

CSS stands for Cascading Style Sheets. CSS finds HTML using a selector and applies visual rules to it.

A CSS rule
.primary-button {
  color: #17130a;
  background: #ffe08a;
  padding: 14px 20px;
  border-radius: 8px;
  font-weight: 800;
}
.primary-button — selector: find elements with this class color — property: what you want to change #17130a — value: the setting you chose { } — block containing the declarations ; — marks the end of one declaration

The box model

margin
border
padding
content

Every element is treated like a box. The content is in the center. Padding creates breathing room inside the border. Margin creates space outside the border.

Reusable color variables

From styles.css
:root {
  --ink: #0b0d10;
  --paper: #fffaf0;
  --gold: #d9a935;
  --gold-bright: #ffe08a;
  --teal: #55d6be;
}

body {
  color: var(--paper);
  background: var(--ink);
}

Variables give important values names. If you later change --gold, every rule using var(--gold) updates together.

Try this: Change --gold-bright to #9ee493, refresh the page, observe the result, and then undo the change.

Language three

JavaScript basics: values, functions, and events

JavaScript is a programming language. It stores information, makes decisions, repeats work, and responds to the visitor.

Variable

const modal = ...

A named place that stores a value.

Function

function openVideo() { }

A reusable group of instructions.

Event

addEventListener("click", ...)

Something the visitor or browser does.

Click behavior
const button = document.querySelector(".play-button");

function sayHello() {
  alert("Hello, Kieron!");
}

button.addEventListener("click", sayHello);
  1. Find the element. querySelector looks through the HTML for the first matching class.
  2. Create the instructions. The function describes what should happen.
  3. Listen for an event. The listener waits for a click and then runs the function.
Plain English: “Browser, find this button. When someone clicks it, run these instructions.”

Create the page shell and connect the files

Minimum index.html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Kieron Christopher Haynes | Portfolio</title>

<!DOCTYPE html>

Tells the browser to use modern HTML rules.

lang="en"

Tells assistive technology that the page is written in English.

<meta charset>

Allows common letters, punctuation, and symbols to display properly.

<meta name="viewport">

Makes the page size correctly on phones.

<link rel="stylesheet">

Connects the HTML to styles.css.

<script src>

Connects the HTML to script.js.

Portfolio section five

Build skill cards and interactive code tabs

The skills area has a static part and an interactive part. The cards are ordinary HTML. The code tabs connect HTML data attributes to JavaScript.

Tab buttons in HTML
<button class="code-tab is-active"
        type="button"
        data-code="game">
  Game Control
</button>

<button class="code-tab"
        type="button"
        data-code="data">
  Data Pipeline
</button>

<pre class="code-window"><code id="codeSample"></code></pre>
Tab behavior in JavaScript
const codeOutput = document.querySelector("#codeSample");
const codeTabs = document.querySelectorAll(".code-tab");

function setCodeSample(name) {
  codeOutput.textContent = codeSamples[name];

  codeTabs.forEach((tab) => {
    tab.classList.toggle(
      "is-active",
      tab.dataset.code === name
    );
  });
}

codeTabs.forEach((tab) => {
  tab.addEventListener("click", () => {
    setCodeSample(tab.dataset.code);
  });
});
  1. The browser finds every element with the code-tab class.
  2. A click listener is attached to each button.
  3. tab.dataset.code reads data-code="game" or another value.
  4. The matching code sample is placed inside #codeSample.
  5. The active class moves to the selected button so CSS can highlight it.
The connection: HTML stores the name, JavaScript reads the name, and CSS styles whichever tab has is-active.

Portfolio section seven

Build film cards and open videos in a modal

A modal is a temporary layer displayed over the page. Each Play Film button stores a YouTube video ID. JavaScript uses that ID to create the embed address.

Film button
<button
  type="button"
  class="play-button"
  data-video="dBq8hv2UvcI">
  Play Film
</button>
Open and close functions
function openVideo(videoId) {
  videoFrame.src =
    `https://www.youtube.com/embed/${videoId}?autoplay=1&rel=0`;
  modal.classList.add("is-open");
  modal.setAttribute("aria-hidden", "false");
  document.body.style.overflow = "hidden";
}

function closeVideo() {
  videoFrame.src = "";
  modal.classList.remove("is-open");
  modal.setAttribute("aria-hidden", "true");
  document.body.style.overflow = "";
}
${videoId}

Inserts the selected video ID inside a template string.

classList.add

Adds a class that changes the modal from hidden to visible.

aria-hidden

Communicates visibility to assistive technology.

body.style.overflow

Stops the page behind the modal from scrolling.

videoFrame.src = ""

Stops the video when the modal closes.

Keyboard accessibility
window.addEventListener("keydown", (event) => {
  if (event.key === "Escape") {
    closeVideo();
  }
});

Advanced feature, explained simply

Understand the animated signal canvas

The faint moving network behind the page is drawn on an HTML <canvas>. A canvas is a blank drawing surface. JavaScript draws small nodes and connecting lines many times per second.

Canvas setup
const canvas = document.querySelector("#signalCanvas");
const ctx = canvas.getContext("2d");
let nodes = [];

function drawSignal() {
  ctx.clearRect(0, 0, width, height);

  nodes.forEach((node) => {
    node.x += node.vx;
    node.y += node.vy;
    ctx.fillRect(node.x, node.y, 2, 2);
  });

  window.requestAnimationFrame(drawSignal);
}
  1. Select the canvas and request its two-dimensional drawing tools.
  2. Store many node objects containing positions and movement speeds.
  3. Clear the previous frame.
  4. Move each node a small amount.
  5. Draw each node in its new position.
  6. Ask the browser to draw the next frame.

The full code also calculates the distance between nodes. If two nodes are close enough, it draws a line between them.

Beginner advice: You do not need to rebuild this effect first. Learn the page structure and simple click events before studying animation loops and coordinate math.

Make it work for everyone

Responsive design and accessibility

Responsive design means the same site adapts to wide monitors, laptops, tablets, and phones. A media query activates CSS only when a condition is true.

Phone layout
@media (max-width: 620px) {
  h1 {
    font-size: 2.35rem;
  }

  .skills-grid,
  .film-grid,
  .education-grid {
    grid-template-columns: 1fr;
  }
}

When the browser is 620 pixels wide or less, the name becomes smaller and multi-column grids become one column.

Accessibility decisions already used in the portfolio

PracticeWhy it helps
Semantic elementsScreen readers understand the page structure.
Heading orderVisitors can navigate the information hierarchy.
Image alt textImages remain meaningful without vision or when loading fails.
Visible focus stylesKeyboard users can see which control is selected.
Escape closes the modalThe film player is easier to dismiss without a mouse.
prefers-reduced-motionThe background animation stops for people who reduce motion.
Strong color contrastText remains readable for more visitors.
Respect reduced motion
@media (prefers-reduced-motion: reduce) {
  * {
    scroll-behavior: auto !important;
    animation-duration: 0.01ms !important;
  }

  #signalCanvas {
    display: none;
  }
}

Safely update images, links, and the résumé

A relative path tells the browser where a file lives compared with the current page.

Résumé update checklist

  1. Export the résumé as a PDF so the layout stays consistent.
  2. Use a clear filename without spaces when possible.
  3. Place it inside assets/resume/.
  4. Search the entire project for the old résumé filename.
  5. Replace every old link with the new path.
  6. Open each résumé button and confirm the PDF loads.
Common mistake: Uploading a new file does not automatically update old links. The HTML must point to the exact new filename.

git status

Shows changed, added, and untracked files.

git add

Selects the files for the next saved version.

git commit -m

Creates the saved version with a short description.

git push

Sends the saved version to the online repository.

Safety habit: Always run git status and review your changes before committing. This helps prevent private or unrelated files from being published.

When something goes wrong

Debugging, practice projects, and your next learning steps

A calm debugging process

  1. Describe the problem precisely. “The résumé button opens a 404 page” is more useful than “the site is broken.”
  2. Identify the responsible layer. Missing content is often HTML; bad spacing is CSS; a dead button is often JavaScript.
  3. Check the browser console. Open developer tools and look for red error messages.
  4. Check spelling and capitalization. Most beginner bugs are small name mismatches.
  5. Undo to the last working version. Test after one small change instead of changing ten things at once.
  6. Search the project. Find every use of a filename, class, ID, or job title before replacing it.
ProblemLikely causeFirst check
CSS does not applyWrong class or stylesheet pathCompare the HTML class and CSS selector character by character
Image does not loadWrong path or filename caseOpen the asset folder and confirm the exact filename
Link does nothingMissing target ID or wrong URLCompare href="#name" with id="name"
JavaScript stopsConsole error or missing elementRead the first red console error and its line number
Mobile layout overflowsFixed width or large contentLook for width values that cannot shrink
Published site looks oldPages build or browser cache delayWait a few minutes and refresh without cache

Beginner glossary and final checklist

Attribute
Extra information inside an HTML opening tag, such as href or class.
Browser
The application that reads website files and displays the page.
Class
A reusable label that lets CSS or JavaScript find one or more elements.
Commit
A named saved version of your project in Git.
Console
A developer-tools panel that displays JavaScript messages and errors.
DOM
The browser’s JavaScript representation of the HTML page.
Element
A complete HTML item, including its tag, content, and closing tag when required.
Event
An action such as a click, key press, scroll, or resize.
Function
A named or reusable set of programming instructions.
GitHub Pages
GitHub’s static website hosting service.
ID
A unique HTML label used for one element, page anchors, or JavaScript selection.
Media query
A condition that activates CSS for a particular screen or user preference.
Modal
A temporary interface layer displayed over the main page.
Property
The part of a CSS declaration that names what will change.
Repository
A Git-tracked project stored on GitHub.
Responsive
A layout that adapts to different screen sizes.
Selector
The part of a CSS rule that chooses which HTML to style.
Semantic HTML
Elements chosen for their meaning, not just their appearance.
Value
The chosen setting in a CSS declaration or a piece of data in JavaScript.
Variable
A named place for storing data in code.
